**关于路径**：文中所有路径都相对于工作区根目录 `<工作区>`（即本项目所在目录）。

## 0. 一句话流程

```
串口发 reset dfu（或 BOOT0 冷启动）
  → 确认 dfu-util -l 能看到设备且 devnum 变化
  → dfu-util -D <bin>（约 10 分钟，勿设短超时）
  → 断电重启（必须物理重启，软件复位无效）
  → 串口读 version 验证 / 抓屏验证
```

## 3. 刷写前必须理解的三个事实

### 3.1 设备有电池，**"断电"不等于复位 MCU**

插着 USB 拨动电源开关，MCU 不会真正重启。判断是否真复位只有一个可靠信号：
**`dfu-util -l` 里的 `devnum` 变了**。如果 devnum 一直是同一个数字，说明 MCU 根本没重启。

### 3.2 DFU 状态机会"假死"

被打断/异常退出后，设备会处于"**接受命令但完全不执行**"的状态：
擦除、写入都返回成功，但回读内容一个字节都不变。

现象：`dfu-util -D` 卡在 `Erase 0%`，或自定义脚本报告 rc 正常但 flash 无变化。

恢复办法（按优先级）：

1. **软件清状态**：发 `DFU_ABORT`(0x21,6) + `CLRSTATUS`(0x21,4)，循环直到 `GETSTATUS` 返回 `bState=2 (dfuIDLE)`
2. **USB 复位**：libusb 的 `libusb_reset_device()`（只能清枚举，不能复位 MCU）
3. **真正的断电重启**（唯一彻底的办法）：

```
拔 USB → 电源开关 OFF → 数 3 秒 → 电源开关 ON → 插 USB
```

若应用本身已损坏（白屏、无 USB），必须靠硬件：

```
拔 USB → 开关 OFF → 把 PCB 边缘标记 VDD 和 BOOT0 的两个焊点短接
  → 开关 ON（屏幕变白，此时已进入 ROM bootloader）
  → 再插 USB（电脑出现 STM32 BOOTLOADER）
```

官方出处：<https://groups.io/g/tinysa/wiki/32458>

### 3.3 驱动必须是 WinUSB

Windows 默认给 DFU 设备装的是 ST 的 `STTub30`，`dfu-util` 打不开（报 `Cannot open DFU device 0483:df11`）。
必须用 **Zadig → Options → List All Devices → "STM Device in DFU Mode" → WinUSB → Replace Driver**。

判定：`dfu-util -l` 能正常列出 `Found DFU: [0483:df11] ... @Internal Flash /0x08000000/064*0002Kg`。

## 4. 刷写步骤

### 4.1 进入 DFU

**方式 A（应用正常时，推荐）**：串口发命令

```powershell
# 以 115200 打开串口，发送文本 "reset dfu\r"
pwsh -File <工作区>/tinysa-cn/tools/tsa.ps1 -Cmd @('reset dfu') -Wait 500
```

**方式 B（应用已坏）**：见 3.2 的 BOOT0 流程。

进入后等待约 4 秒，确认：

```powershell
& <工作区>/tinysa-src/official/dfu-util-static.exe -l
# 必须看到 Found DFU: [0483:df11]
```

### 4.2 清状态到 dfuIDLE

发 `ABORT`+`CLRSTATUS` 直到 `GETSTATUS` 的 `bState == 2`。
现成实现见 `tools/dfuse.py`（含 `to_idle` 逻辑）。

**不要跳过这一步**，状态不干净时擦除会卡在 `Erase 0%`。

### 4.3 刷写

```powershell
& <工作区>/tinysa-src/official/dfu-util-static.exe `
    -a 0 -s 0x08000000:leave -D <工作区>/tinysa-cn/dist/<固件>.bin
```

- **耗时约 10 分钟**（实测约 190 B/s，瓶颈是这颗 F072 的 DFU 状态轮询间隔，不是 USB 带宽）
- **绝对不要把超时设成几分钟**——会把自己的刷写杀掉（踩过，在 34% 处中断）
- 期间不要操作电源、不要插拔
- 以下警告**正常，可忽略**：
  - `Invalid DFU suffix signature`
  - 报某个与本设备无关的 USB 设备打不开

成功标志：

```
Download done.
File downloaded successfully
Transitioning to dfuMANIFEST state
```

### 4.4 重启（必须物理重启）

刷完设备停在 `dfuMANIFEST`，**软件复位不会启动新固件**（`libusb_reset_device` 试过，无效）。

```
拔 USB → 电源开关 OFF → 数 3 秒 → 电源开关 ON → 插 USB
```

> 如果仍显示旧界面，说明 MCU 又没真复位——看 3.1，检查 devnum 是否变化。

### 4.5 验证

```powershell
# 1) 串口 (115200) 读版本
pwsh -File <工作区>/tinysa-cn/tools/tsa.ps1 -Cmd @('version') -Wait 800

# 2) 抓屏（先点一下屏幕打开菜单）
pwsh -File <工作区>/tinysa-cn/tools/tsa.ps1 -Cmd @('touch 150 120','release') -Wait 500 `
     -Capture <工作区>/tinysa-cn/out/check.bin
python <工作区>/tinysa-cn/tools/screen.py bin2png `
     <工作区>/tinysa-cn/out/check.bin <工作区>/tinysa-cn/out/check.png
```

抓屏原理：串口发 `capture\r`，随后读取 **320×240×2 = 153,600 字节** RGB565（大端）。

## 5. 固件是怎么改出来的（改代码时看这里）

### 5.1 编码方案

```
ASCII : 原样 1 字节
汉字  : 2 字节  [ 0x80 | (idx>>7) ] [ 0x20 + (idx & 0x7F) ]
解码  : idx = ((hi & 0x7F) << 7) | (lo - 0x20)
```

> ⚠️ 低字节刻意避开 `0x00 / 0x08 / 0x09 / 0x0A`。
> 否则会被字符串函数当成 NUL / 退格 / 换行。
> 另外低位必须用**加法** `0x20 + (i & 0x7F)`，用按位或会大量撞码（踩过）。

### 5.2 字库

- 12×12 → **14×15**（升级过两次），268 字，`const` 放 Flash，**不占 RAM**
- 生成器：`tools/gen_font.py`，输出 `out/cjkfont.c` + `out/cjkfont.h` + `out/glyphmap.json`
- 字号规则：`FONT_SIZE = GH - 1`。
  > ⚠️ 曾经把 `FONT_SIZE` 写死成 12，导致"格子变大了字没变大"。
- 字模必须填满格子，否则屏幕上看不出变化

### 5.3 绘制挂接点（`ili9341.c`）

在三条路径里加了中文分支，全部调用 `ili9341_blitBitmap(x, y, CJK_W, CJK_H, cjk_glyphs[idx])`：

| 函数 | 用于 |
|---|---|
| `ili9341_drawstring` | 5×7 小字 |
| `ili9341_drawstring_7x13` | 菜单标签（主要战场） |
| `ili9341_drawstring_10x14` | 表单/键盘按钮 |

**没有**给 `lcd_printf` 的流式输出（`lcd_put5x7` / `lcd_put_7x11b`）加中文支持——
它按单字节走，遇到 0x80+ 会越界索引 5×7 字模表，屏幕上出乱码。所以走这条路的字符串**必须保持英文**。

### 5.4 打补丁流水线

```
labels/menu_zh.csv  →  gen_font.py  →  patch_ui2.py  →  postfix.py  →  make
   (译文表)            (字库+码表)      (替换源码字符串)   (强制保留英文的位置)
```

**`patch_ui2.py` 用逐字符词法扫描，不要改回正则。**

> 第一版用正则 `"..."` 匹配，遇到字符字面量/注释里的引号会**失步**：
> 匹配数远少于引号对数，`menu_top[]` 整段被跳过，结果固件是新的、菜单却是英文。
> 症状极具迷惑性——串口 version 显示正确版本号，但界面全英文。

**`postfix.py` 做三件必须的事**：

1. 左信息栏/流式路径恢复英文：`PAUSED`、`ARMED`、`AM`、`Spur: AUTO/OFF/ON`、`LNA:ON`
2. 左栏版本号固定为短标识（原逻辑写死从版本串固定偏移截取，长版本名会溢出重叠）
3. 版本页底部插入署名行

重建字库前注意：`out/used_chars.txt` 若存在会触发裁剪，**不要保留**，
否则会砍掉仍被字典引用的字，屏幕上出现 `?`。

### 5.5 左信息栏为什么保留英文

左栏是 5×7 字模、**行距只有 8px**，12px 以上的汉字会压到下一行。
所以 `Atten / RBW / Scan / PAUSED / ARMED / AM` 一律保持英文缩写。

## 8. 故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `Cannot open DFU device 0483:df11` | 驱动是 STTub30 | Zadig 换 WinUSB |
| `dfu-util -D` 卡在 `Erase 0%` | DFU 状态假死 | ABORT+CLRSTATUS 清到 dfuIDLE，或断电重启 |
| 命令都"成功"但 flash 没变 | MCU 没真复位 | 断电重启；确认 devnum 变化 |
| 刷完重启仍旧界面 | 同上 | 检查电源开关是否真的断电 |
| 开机白屏、电脑不认 | 固件损坏 | BOOT0 短接 VDD 进 DFU 重刷 |
| 菜单仍英文但版本号是自定义的 | 补丁器失步（正则版） | 用 `patch_ui2.py` 重打补丁 |
| 屏幕出现 `?` | 字库被裁剪、缺字模 | 删除 `out/used_chars.txt` 重新生成 |
| 中文显示乱码方块 | 字符串走了 `lcd_printf` 流式路径 | 该字符串改回英文 |
| 左栏文字重叠 | 长版本名溢出 8 字节缓冲 | 左栏用短标识 |

## 10. 已知限制

- 界面绘制按 2 字节取字模，开销比 ASCII 略高，菜单刷新无可感差异
- 只有 268 个汉字的子集，**新增译文必须重跑字库流水线**，不能用未收录的字
- 左信息栏永远英文（8px 行距的硬限制）
- 串口控制台、脚本协议保持 ASCII，脚本兼容性不受影响
- 刷写速度无法优化到更快（设备 DFU 实现限制，块大小必须 ≤1024，2048 会卡死）
